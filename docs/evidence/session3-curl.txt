=== Exercise 6: SignalR groups, reconnect, backplane awareness ===

Two browser tabs connected via /hubs/tms:
- Tab 1: ?studentId=1
- Tab 2: ?studentId=2

POST /api/v2/transcripts {"studentId": 1} (fresh reportId, no idempotency key):
- Tab 1 console: "Transcript ready: <reportId> at /api/v2/transcripts/<reportId>/download"
- Tab 2 console: nothing (message correctly scoped to student-1 group only)

Server log confirms group-targeted dispatch, not broadcast:
  "Transcript ready, notification sent: <reportId> to student-1"

Reconnect test: API process restarted mid-session while both tabs connected.
- Both tabs' WebSockets dropped (code 1006)
- withAutomaticReconnect fired on schedule: attempt 1 (0ms), attempt 2 (2s),
  attempt 3 (10s), attempt 4 (30s) per tab, matching configured backoff
- Both tabs successfully reconnected once the new process was listening
  ("HubConnection reconnected successfully", new connection id logged)
- A transcript POST issued after the restart was still correctly delivered
  to the reconnected tab 1 client only; tab 2 received nothing

Clients.All is not used anywhere in the codebase — all dispatch goes through
Clients.Group(GroupNames.Student(...)).
